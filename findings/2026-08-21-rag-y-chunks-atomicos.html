RAG e historial conversacional

El runtime usa un corpus atómico, filtros narrativos deterministas y un prompt cuyo historial no arrastra pasajes recuperados.

Decisión

El runtime usa exclusivamente los 162 chunks atómicos derivados de las 15 escenas. Cada chunk expresa un dato específico y breve; conserva source_excerpt, parent_chunk_id, líneas canónicas, permisos de conocimiento, hechos, hitos y nivel de spoiler.

La procedencia y la metadata controlan el retrieval, pero no se inyectan completas en el prompt. El índice activo es backend/data/rag_index_atomic_embeddinggemma_two.sqlite3, construido con embeddinggemma-300m y dos preguntas canónicas por chunk.

Prompt efectivo

El system permanece estable: reglas comunes y persona breve. Los turnos terminados contienen únicamente mensajes user y assistant.

<retrieved_context>
Dato atómico permitido para este personaje y estado: ...
</retrieved_context>

<user_message>
Pregunta del jugador...
</user_message>
ImportanteEl bloque recuperado pertenece solo al turno actual. No se persiste en el historial.

Flujo de un turno

  1. Se embebe la pregunta actual.
  2. Se filtran NPC, canal, hitos, hechos y spoilers.
  3. Se combinan similitud coseno y BM25 con RRF.
  4. Se elige un focus y, como máximo, un apoyo compatible.
  5. Se genera una única respuesta.
  6. Al terminar correctamente, se registran hechos y derivaciones.
